# CSS面试题

## 说说你对盒子模型的理解?

在 CSS 中，盒子模型规定了浏览器在渲染网页时，如何把每一个 HTML 元素看作是一个矩形的盒子，并处理这些盒子的尺寸、边距和位置关系。

- 标准盒模型（W3C Standard Box Model / content-box）：你设置的 width 和 height 只包含 Content（内容区），不包括 padding 和 border，当你给元素增加 padding 或 border 时，整个盒子会被撑大，容易导致布局错位。

- IE 盒模型 / 怪异盒模型（border-box）：修改 padding 或 border 时，盒子的可视总宽度保持不变，更符合直觉，常用于现代布局。

1. margin 的合并（外边距折叠）：垂直方向上，相邻的两个普通文档流块级元素的 margin 会发生合并，取两者中的较大值（而不是相加）。
2. margin 的负值：margin 可以为负值，常用于实现拉近距离、微调定位、制作特殊布局（如负外边距实现圣杯/双飞翼布局的自适应）。
3. BFC（块级格式化上下文）：盒子模型常与 BFC 结合考察，BFC 是一个独立的渲染区域，可以用来防止垂直方向 margin 折叠、包含浮动元素（清除浮动）等。

## css选择器有哪些？优先级？哪些属性可以继承？

1. 基础选择器

- 通用选择器：*，匹配页面上所有的元素。
- 标签选择器（元素选择器）：如 div、p、h1，匹配特定 HTML 标签。
- 类选择器：如 .box、.active，匹配带有指定 class 属性的元素。
- ID 选择器：如 #header，匹配带有指定 id 属性的元素（在一个页面中应是唯一的）。

2. 复合/关系选择器

- 后代选择器：空中格，如 div p，匹配 div 内部所有的 p 元素（无论嵌套多深）。
- 子代选择器：>，如 ul > li，仅匹配直接子元素。
- 相邻兄弟选择器：+，如 h1 + p，匹配紧跟在 h1 后面的第一个兄弟 p 元素。
- 通用兄弟选择器：~，如 h1 ~ p，匹配 h1 后面所有的兄弟 p 元素。
- 并集选择器（选择器列表）：,，如 h1, h2, .title，同时为多个选择器定义的元素设置相同样式。

3. 属性选择器，如 [type="text"]、a[href^="https"]，根据元素的属性及其值来匹配元素。

4. 伪类选择器（用于选择元素的特定状态或结构）

- 状态伪类：:hover（悬停）、:focus（聚焦）、:active（激活）、:checked（选中）。
- 结构伪类：:nth-child(n)、:first-child、:not()（否定伪类）。

5. 伪元素选择器（用于样式化元素的特定部分），如 ::before（在元素内容前插入内容）、::after（在内容后插入）、::first-letter（首字母）

## 说说em/px/rem/vh/vw区别?

- px: 绝对单位, 物理像素 / 屏幕分辨率像素，适合用于边框、不需要缩放的固定尺寸
- em: 相对单位, 当前元素（自身）的 font-size，适合用于局部组件缩放、首行缩进、首字母放大，最佳实践：适合用于控制组件内部的相对比例。例如设置按钮的 padding: 0.5em 1em;，这样只要改动按钮的 font-size，按钮的内边距就会等比例缩放。
- rem: 相对单位, 根元素（`<html>`）的 font-size，避免了 em 的多层嵌套累加问题，只需要修改全局 `<html>` 的字体大小，整页所有使用 rem 的元素都会等比例缩放，是移动端响应式布局的经典方案。
- vw: 相对单位, 视口（Viewport）的宽度（1vw = 1% 视口宽），适合用于视口等比例缩放、全屏容器
- vh: 相对单位, 视口（Viewport）的高度（1vh = 1% 视口高），适合用于落地页、全屏一屏式布局、粘性底部

## 说说设备像素、css像素、设备独立像素、dpr、ppi 之间的区别？

1. 设备像素 (Device Pixels, 简称 DP) —— 物理硬件的最小发光点

- 定义：也叫物理像素。它是屏幕显示器上一个真实的、物理存在的发光点（由红绿蓝 RGB 像素组成）。
- 特点：在手机出厂时就已经固定死了，无法通过软件修改。

2. PPI (Pixels Per Inch) —— 屏幕的像素密度

- 定义：每英寸所拥有的物理像素数量。
- 计算：由屏幕的物理尺寸和分辨率决定。PPI 越高，屏幕看起来就越细腻，越没有颗粒感。

3. 设备独立像素 (Device Independent Pixels, 简称 DIP) —— 操作系统的逻辑单位

- 定义：也叫逻辑像素。它是操作系统（如 iOS / Android）为了方便软件开发者而引入的虚拟单位（在 Android 中对应 dp，在 iOS 中对应 pt）。
- 为什么需要它：如果直接用物理像素开发，当屏幕变高清（物理像素翻倍）时，原本 100 像素宽的按钮在高清屏上会直接缩小成一半，变得极小。为了让同样大小的按钮在不同分辨率的屏幕上“看起来尺寸差不多”，操作系统便使用“设备独立像素”来统一尺寸。

4. CSS 像素 (CSS Pixels) —— 网页开发的标准单位

- 定义：我们在 CSS 中写的 px。
- 关系：在缩放比例为 100% 的情况下，1个 CSS 像素 = 1个设备独立像素。
- 特殊情况：当用户在浏览器中双指放大网页到 200% 时，1个 CSS 像素就会变成原来的 2 倍宽，此时 1个 CSS 像素可能就会占据更多的设备独立像素和物理像素。

5. DPR (Device Pixel Ratio) —— 物理与逻辑的桥梁（设备像素比）

- 定义：设备像素（物理像素）与设备独立像素（逻辑像素）的比例关系。

## css中有哪些方式可以隐藏页面元素？有什么区别?如果同时还要保证屏幕阅读器可用呢？

1. ```display: none;```：最彻底的隐藏。元素直接从渲染树（Render Tree）中移除，不占据任何排版空间。因为彻底不存在了，所以鼠标点不到，屏幕阅读器也直接无视它。
2. ```visibility: hidden;```：相当于变成了“隐形人”。元素空间依然保留（页面会留白），但你看不到它。具有继承性：如果父元素设置了隐藏，子元素也会隐藏；但如果子元素单独设置 visibility: visible;，子元素会重新显示。
3. ```opacity: 0;```：只是把透明度调到了 0。它依然占据空间，并且最致命的是它仍然可以被点击、聚焦和响应各种 JS 事件，屏幕阅读器可阅读。
4. ```content-visibility: hidden;```：现代 CSS 属性，主要用于性能优化。它会跳过该元素及其子元素的渲染（包括布局和绘制），能极大提升长页面的滚动和加载性能。

保证屏幕阅读器可用的最佳实践：经典无障碍隐藏类（.sr-only / .visually-hidden），其核心原理是：让元素保持在渲染树中，但不设置 display: none，而是通过绝对定位将其裁剪到一个 1px * 1px 极小的隐藏区域中，并移出可视区，视觉上完全消失，不占用物理空间，但因为它在 HTML 结构中正常存在且未被标记为隐藏，屏幕阅读器可以完美地朗读它。

## 元素水平垂直居中的方法有哪些？如果元素不定宽高呢？

1. Grid 布局：```place-items: center```
2. Flex 布局：```align-items: center```
3. 绝对定位 + transform: translate(-50%, -50%)
4. Flex/Grid 配合 margin: auto

如果需要兼容IE9 等老版本浏览器，需要用以下方法：

- vertical-align: middle + text-align: center：需要将子元素设为 inline-block，且父元素内通常需要一个高度 100% 的伪元素（或空标签）来当作对齐的垂直支点，代码冗长。
- 绝对定位 + 四个方向设为 0 + margin: auto：这种方式必须要求元素有固定的 width 和 height，如果不定宽高，元素会被直接拉伸至填满父元素。

## 如何实现两栏布局，右侧自适应？三栏布局中间自适应呢？

### 双栏布局

1. Flex 布局方案（最常用、最推荐），父元素开启 Flex 生态，左侧固定宽度，右侧设置 flex: 1 自动吞噬剩余的所有空间。
2. Grid 布局方案（最直观），直接在父级划分列宽，第一列 200px，第二列 1fr（1个网格单位，代表剩余全部空间）。

### 三栏布局

1. Flex 布局方案（顺应标准流结构），左右两边设置固定宽度，中间设置 flex: 1。
2. Grid 布局方案（优雅至极），通过 grid-template-columns 一行代码定义三列规则。

### 圣杯布局（Holy Grail Layout）

- 原理：三栏全部设置 float: left。中间 center 宽度设为 100%。
- 位移：左栏设置 margin-left: -100% 把它拉回最左边；右栏设置 margin-left: -右栏宽度 把它拉回最右边。
- 防覆盖：此时中间内容会被左右栏挡住，所以给父元素加上 padding: 0 右栏宽 0 左栏宽。再利用 position: relative 把左右两栏移到 padding 的空白区域。

### 双飞翼布局（淘宝早期经典方案）

- 原理：同样是全部 float: left，中间 center 宽度 100%，左右栏利用负 margin 回位。
- 防覆盖：它不改动父元素的 padding，而是在 center 里面再套一个子元素 div，直接给这个内部 div 设置 margin: 0 右栏宽 0 左栏宽，把文字挤到中间去。

## 说说flexbox（弹性盒布局模型），以及适用场景？

### 一、核心概念：一轴、双体、两方向

要理解 Flexbox，必须先掌握它的核心术语：

1. 容器（Flex Container）与 项目（Flex Item）：

- 任何元素只要设置了 display: flex; 或 display: inline-flex;，它就变成了 Flex 容器。
- 该容器的直接子元素会自动成为 Flex 项目（不管原本是 block 还是 inline 标签，都会遵循弹性盒规则）。

2. 主轴（Main Axis）与 交叉轴（Cross Axis）：

- Flexbox 布局是沿着轴线进行的。
- 主轴：默认是水平方向（从左到右）。由 flex-direction 属性决定。

### 二、Flexbox 的典型适用场景

Flexbox 是一维布局（一次只能处理“行”或“列”单方向的代码），因此它最适合用在网页局部组件、导航条、列表以及小范围的响应式排版中：

1. 导航栏 / 工具栏（Navigation Bars）

- 特点：左侧是 Logo，右侧是登录和菜单，或者整行菜单均匀分布。
- Flex 解法：设置 justify-content: space-between;，可以完美把两端拉开，中间留空。

2. 水平垂直居中（Absolute Centering）

- 特点：不论内容多大、不定宽高，都要塞在容器正中心（如弹窗、Loading 图标）。
- Flex 解法：justify-content: center; align-items: center;，公认最高频的现代居中写法。

3. 圣杯/两栏/三栏等自适应布局（Adaptive Columns）

- 特点：侧边栏固定（如后台管理菜单），主体内容区随着浏览器变大而自动变大。
- Flex 解法：主体区设置 flex: 1;，侧边栏设置 flex-shrink: 0; width: 200px;。

4. 流式网格 / 卡片平铺（Media Grid / Card Layouts）

- 特点：电商商品的商品卡片、博客的文章卡片列表，一行放 4 个，屏幕小了自动换行。
- Flex 解法：设置 flex-wrap: wrap;，配合子项的宽度或百分比，轻松实现流式卡片平铺。

5. 等高布局（Equal Height Columns）

- 特点：几列内容长短不一，但设计师要求每一列的背景色或边框在视觉上必须“等高”。
- Flex 解法：利用默认的 align-items: stretch;，子项目会自动拉伸至与最高的那一列同等高度。

### 三、避坑经验：什么时候【不适合】用 Flexbox？

虽然 Flexbox 几乎无所不能，但在以下场景中它不是最佳选择：

- 复杂的二维网格布局：如果你需要同时对齐“行”和“列”（比如复杂的报表、大盘看板、拼图式的创意画廊布局），应该优先使用 CSS Grid（网格布局）。Grid 是天生的二维布局利器。
- 超大型页面整体框架：由于 Flex 布局在解析时需要计算子元素的动态弹性，若用来嵌套整个网站最外层的超大骨架，可能会引发微小的性能损耗。通常建议最外层大骨架用 Grid 或标准流，组件内部全面拥抱 Flexbox。

## 介绍一下grid网格布局，Grid 布局的优势在哪里

CSS Grid（网格布局） 是 CSS 中最强大的二维布局系统。
与一维的 Flexbox（一次只能处理一行或一列）不同，Grid 布局允许我们将网页划分成行（Rows）和列（Columns）的网格结构，从而能够同时在水平和垂直两个方向上控制元素的位置和大小。

一、Grid 布局的核心概念

1. 网格容器（Grid Container）与网格项目（Grid Item）：

- 任何元素设置了 display: grid;，就成为了网格容器，其直接子元素自动成为网格项目。

2. 网格线（Grid Lines）：

- 划分网格的横线和竖线。如果有 3 列，就会有 4 条垂直网格线。我们可以通过网格线的编号（1, 2, 3...）来精准定位元素。

3. 网格轨道（Grid Track）：

- 两条相邻网格线之间的空间，实际上就是网格的某一行或某轻一列。

4. 网格单元格（Grid Cell）：

- 网格中的最小单位，由一条行轨道和一条列轨道交叉组成（类似 Excel 的单个单元格）。

5. 网格区域（Grid Area）：

- 由多个单元格组合而成的矩形区域，可以通过指定起始和结束的网格线来划定。

二、Grid 布局的绝对优势 

为什么说 Grid 是现代 CSS 布局的终极利器？相比传统的浮动和 Flexbox，它的优势主要体现在以下几个方面：

1. 真正的二维布局能力

Flexbox 擅长“排成一排”，当元素换行时，下一行的元素和上一行的元素很难建立垂直方向的对齐关系。而 Grid 天生就是为了图表、画廊、仪表盘等行、列必须严格对齐的复杂界面设计的，控制能力达到了像素级。

2. “不改变 HTML 结构”的响应式重排

在过去，想要在手机端把“右侧边栏”移动到“顶部”，通常需要用 JS 动态修改 DOM，或者写两套 HTML 代码。
使用 Grid 布局，你只需要在媒体查询（Media Queries）里重新定义父容器的 grid-template-areas，就能任意颠倒、重组子元素的视觉顺序，而 HTML 源码不需要动一个字。

3. 彻底告别复杂的内外边距（Margin / Padding）计算

在过去为了做网格平铺，我们需要给子元素设置 width: 23%; margin-right: 2%;，还要单独写 :last-child { margin-right: 0; } 来防止换行撑爆。

三、经典适用场景

1. 网站整体大骨架（Layouts）：传统的顶部导航、左侧菜单、中间内容、底部页脚，一行 Grid 即可搞定。
2. 大屏可视化仪表盘（Dashboards）：各种错落有致、大小不一的图表卡片拼接。
3. 创意瀑布流 / 图片画廊（Photo Galleries）：有些图跨两行，有些图跨两列，拼凑成极具设计感的艺术墙。
4. 电商商品网格（E-commerce Product Grids）：严格对齐且具备完美响应式收缩的商品列表。

四、Grid 与 Flexbox 如何选型？

- 用 Grid 规范大局：用 Grid 来划分整个页面的首层大骨架，或者复杂的二维网格组件。
- 用 Flex 雕琢局部：在网格的每一个单元格内部，如果里面的小图标和文本需要水平对齐、垂直居中，依然首选 Flexbox。

## 请描述 BFC(Block Formatting Context) 及其如何工作

BFC（Block Formatting Context，块级格式化上下文）是 Web 页面可视化 CSS 渲染中的一个独立布局环境，它规定了内部块级元素的排列规则，并且与外部元素完全隔离、互不影响。

1. 垂直顺序排列：内部的块级盒子（Block-level Box）会在垂直方向上一个接一个地从上往下排列。
2. 同源 margin 折叠，异源隔离：属于同一个 BFC 的两个相邻块级盒子的上下 margin 会发生折叠（取较大值，即 Margin Collapsing）；但分属不同 BFC 的盒子之间不会发生 margin 折叠。
3. 贴靠左边缘：每个子元素的左外边距（margin-left）会紧贴包含块（父容器）的左边框（border-left），即使存在浮动元素也是如此（除非该子元素自己也触发了新的 BFC）。
4. 不与外部浮动重叠：BFC 自身的区域不会与外部的 float 盒子发生重叠（它会自动避让浮动元素，填满剩余可用宽度）。
5. 计算高度时包含内部浮动：计算 BFC 容器的高度时，其内部脱离文档流的浮动子元素（float: left/right）也会参与高度计算。

## 列举不同的清除浮动的技巧，并指出它们各自适用的使用场景

1. ::after 伪元素法（Clearfix），在父元素末尾插入隐藏块级伪元素并设置 ```clear: both```，是最推荐的标准方案。不增加多余 HTML 节点，不会裁剪溢出内容。
2. display: flow-root（现代 BFC），直接在父元素上设置 ```display: flow-root;```，最简洁优雅的现代方案。创建一个 BFC，不支持极老旧的 IE 浏览器（现代浏览器已全面支持）。
3. 在父元素上设置 ```overflow: hidden 或 auto```， 触发 BFC，兼容性极好（支持所有历史浏览器），有副作用大，会裁剪超出父容器的阴影（box-shadow）、下拉菜单或 Tooltip，或出现意外滚动条。
4. 在浮动元素末尾添加 `<div style="clear: both;"></div>`，全浏览器兼容，在页面中增加了无用 DOM 节点，增加维护成本。

## 你会如何解决特定浏览器的样式问题？

## 请罗列出你所知道的 display 属性的全部值，它们的区别是什么

grid：将元素设为块级网格容器。最强大的二维布局系统（同时控制行和列）。

list-item：模拟 `<li>` 标签。使元素像列表项一样生成一个项目符号（如圆点）和内容块。通常配合 list-style 属性使用。
contents：“神秘消失”容器。让设置了该值的标签在布局上“隐形”，但它的子元素会正常显示。子元素会直接变成该标签父容器的直接子元素。非常适合用来包裹代码但不想影响 Flex/Grid 布局的场景。
flow-root：创建一个新的块级格式化上下文 (BFC)。最优雅的清除浮动 (clear float) 方式，能完美包裹内部浮动的子元素，解决高度塌陷问题。

## 为什么会发生样式抖动

### 一、 核心原因

1. 异步资源加载未设置尺寸（最常见）

当页面上的图片、广告位或 iframe 异步加载时，如果我们在 HTML/CSS 中没有提前为它们声明宽度和高度，浏览器在初始渲染时会认为该元素的宽高为 0。

- 发生抖动：当图片或广告突然下载完成并注入页面时，它会瞬间撑开容器，将下方的所有文本和元素强行“往下推”，导致视觉上的剧烈跳动。

2. 字体加载引发的样式切换（FOUT / FOIT）

当网站使用自定义 Web 字体（如谷歌字体或特殊艺术字）时，字体文件的下载是异步的。

- 发生抖动：在字体下载完成前，浏览器可能会先用系统的默认字体（如宋体、Arial）渲染文字（FOUT），或者直接让文字隐形（FOIT）。当自定义字体下载完毕后，文字会突然改变大小、字宽和样式，导致段落行数或排版发生改变，从而引发页面抖动。

3. JS 触发了“布局挤压”（Layout Thrashing）

在 JavaScript 中，连续、交替地执行“读取 DOM 几何属性”和“修改 DOM 样式”会强迫浏览器进行多次昂贵的同步布局计算。

4. 主题配置/国际化初始化的“时间差”

正如前面讨论多主题配置时提到的，如果你在页面加载后，通过 JS 在 DOMContentLoaded 或 window.onload 事件中才去判断并赋予 body 类名（如 .dark），或者才去动态注入 CSS 变量：

- 发生抖动：用户会先看到 0.1 秒的默认亮色（或无样式）页面，随后 JS 执行，页面瞬间变成暗黑模式或正确的主题，造成视觉闪烁和抖动（也称 FOUC，Flash of Unstyled Content）。

### 二、 解决方案与最佳实践

1. 永远为媒体资源预留空间

- 对于图片、视频和广告，明确写出 width 和 height 属性，或者使用 CSS 的 aspect-ratio（宽高比） 属性。这样即使图片还没加载出来，浏览器也能提前在页面上“抠出”一块正确大小的空白占位。

2. 优化字体加载策略

- 充分利用 font-display: swap; 属性。它告诉浏览器：在自定义字体下载好之前，先用系统字体顶替，且两者的切换要尽可能平滑。同时，尽量让系统备用字体的大小和自定义字体接近。

3. 读写分离（避免 Layout Thrashing）

- 避免在循环中交替读写 DOM。正确的做法是先统一读取，再统一修改：javascript
- 也可以借助 requestAnimationFrame 将修改样式的操作推迟到浏览器的下一次刷新帧中执行。

4. 将初始化脚本前置（防闪烁）

- 对于主题、语言包等影响全局样式的逻辑，不要放在大包（Bundle）里异步加载。应该写一段极其精简的原生 JS 脚本，直接内联在 HTML 的 `<head>` 顶部。这样在浏览器开始渲染任何 DOM 节点之前，主题类名就已经挂载好了。

- 原理：将主题配置抽象为一个 JS 对象（包含各种颜色、阴影等键值对），切换主题时通过 JavaScript 遍历对象并批量设置到 document.documentElement.style.setProperty('--xxx', value)。

## 简述 css 中 position 的值

1. static（默认值）：静态定位，元素按照正常的文档流（从上到下、从左到右）自然排列，此时设置 top、bottom、left、right 以及 z-index 属性全部无效。

2. relative：相对定位，元素不脱离文档流，它原本占有的物理空间依然会被保留（不会塌陷），通过 top/bottom/left/right 进行偏移时，是相对于该元素在常规流中的原本位置进行移动，常用于做绝对定位（absolute）子元素的父级参照物（即著名的“子绝父相”）。

3. absolute：绝对定位，元素完全脱离文档流，不再占据原本的物理空间，后面的元素会顶上来，相对于最近的非 static（通常是 relative、absolute 或 fixed）的祖先元素进行定位。如果一路上找不到这样的祖先，则相对于整个网页的根元素（`<html>`，即初始包含块）定位。

4. fixed：固定定位，元素完全脱离文档流，永远相对于浏览器视口（Viewport）进行定位。无论页面如何滚动，它都死死固定在屏幕的某个位置，回到顶部按钮、固定的网站顶部导航栏、右下角悬浮广告。

5. sticky：粘性定位，它是 relative 和 fixed 的结合体，在页面滚动到指定阈值之前，它表现为正常的 relative；当页面滚动超过这个阈值时，它会瞬间“粘”在屏幕指定位置，表现为 fixed。但它的活动范围受限于其父容器，父容器滚出屏幕时它也会跟着滚走，表格的吸顶表头（Header）、滚动列表的字母侧边栏、文章长目录的侧边跟随。

6. inherit：继承定位，规定元素从父元素继承 position 属性的值（较少直接使用，除非在特定的组件复用场景下需要强制同步行为）。

## rem、em、vw、vh 的值各是什么意思

1. rem（Root em）：网页根元素（即 `<html>` 标签）的字体大小，移动端响应式布局的基石。只要通过 JavaScript 或媒体查询根据屏幕宽度动态修改 `<html>` 的字号，整个页面所有用 rem 定位的元素、间距、字号都会等比例缩放。

2. em： 当前元素的字体大小。如果当前元素本身没有设置字号，则参考其父元素的字体大小，若当前元素 font-size: 20px，那么该元素的 width: 2em 就会被计算为 40px，如果在 font-size 属性本身上使用 em（例如 font-size: 1.5em），它参考的是父元素的字号，首行缩进（text-indent: 2em 刚好缩进两个字）、组件局部等比例缩放（如按钮的内边距 padding 随字号大小自动调整）。

3. vw（Viewport Width）

- 意思是： 视口（屏幕可视区域）宽度的 1%。
- 计算规则： 整个屏幕宽度固定为 100vw。如果手机屏幕宽度是 375px，那么 1vw = 3.75px，50vw = 187.5px（刚好是一半宽度）。
- 应用场景： 页面容器的宽度自适应、大屏可视化。

4. vh（Viewport Height）

- 意思是： 视口（屏幕可视区域）高度的 1%。
- 计算规则： 整个屏幕高度固定为 100vh。如果屏幕高度是 800px，那么 1vh = 8px。
- 应用场景： 全屏海报、单页滚动（H5翻页效果）、通栏大图背景，确保内容刚好铺满一屏。

## normalize.css 与 reset.css 又何区别

### reset.css

- 做法：将所有浏览器的默认样式（如 margin、padding、font-size 等）全部清零或重置。
- 理念：“众生平等”。把所有元素的默认样式抹平，让页面在一个完全白纸（归零）的基准上从头开始写。
- 缺点：过于暴力，像 `<h1>` 的加粗变大、`<ul>` 的缩进等有用的默认样式也被删掉了，开发者后面往往还要手动把它们加回来。

### normalize.css

- 做法：保留有价值的浏览器默认样式，只对不同浏览器之间存在差异的样式进行“标准化”修正。
- 理念：“该保留的保留”。比如它会保留 `<h1>` 的字号、`<ul>` 的内边距等，同时修复各浏览器的 CSS Bug。
- 优点：更符合浏览器的本意，省去了不少重复编写基础排版样式的功夫。

## 如何实现三列均分布局

1. Grid 布局方案（最推荐，代码最少）

核心原理：直接在父容器上通过 1fr（1个网格单位）定义三个等宽的轨道，配合 gap 属性设置间距时，浏览器会自动减去缝隙宽度后再进行均分，完全不需要你计算。

2. Flex 布局方案一：flex: 1 均分，父容器开启 Flex 布局，每个子项目都设置 flex: 1，让它们公平、等比例地瓜分父容器的水平空间。

3. Flex 布局方案二：固定比例 flex-basis: 33.33%

如果你希望子项目严格锁定为总宽度的三分之一，可以使用百分比，如果使用了 gap 间距，百分比加上间距可能会撑爆容器导致换行。为此，需要配合 calc() 函数自动扣除间距。

4. 传统方案：百分比宽度 + box-sizing，如果你的项目必须兼容极老版本的浏览器，可以使用传统的 float 或 inline-block 配合 width: 33.33%，避坑关键：必须设置 box-sizing: border-box，否则如果列内部有 padding 或 border，总宽度会超过 100% 导致第三列掉下去。

## CSS有哪些伪类与伪元素选择器

### 一、 伪类选择器（Pseudo-classes）

概念：伪类用于选择处于特定状态的元素，或者满足特定结构关系的元素。它就像是为满足条件的元素临时添加了一个虚拟的 class。

### 二、 伪元素选择器（Pseudo-elements）

- ::before：在被选元素的内容前面插入虚拟内容。
- ::after：在被选元素的内容后面插入虚拟内容。
  - 关键要求：这两个伪元素必须配合 content 属性才能生效，即使内容为空（content: "";）。
  - 场景：常用于清除浮动、小图标装饰、面包屑分隔符等。
- ::first-letter：选择块级元素内部文本的第一个字母/汉字（常用于报刊杂志式的首字下沉放大效果）。
- ::first-line：选择块级元素内部文本的第一行（会随着浏览器窗口宽度的改变动态计算第一行）。
- ::selection：匹配用户在网页上鼠标高亮选中的文本部分。可以用它来定制划词选中时的背景色和文字颜色。
- ::placeholder：匹配表单输入框的占位提示文本（placeholder）的样式。

## css加载会阻塞DOM树的解析和渲染吗

CSS 加载不会阻塞 DOM 树的解析，但必然会阻塞 DOM 树的渲染。此外，它还会阻塞后续 JavaScript 脚本的执行。

对性能优化的启发：

1. CSS 丢在 `<head>` 中：尽早让浏览器发现并并行下载 CSS，加速 CSSOM 的构建。
2. 缩小 CSS 体积：利用 Webpack/Vite 压缩 CSS，并剔除无用代码（Unused CSS）。
3. 首屏关键 CSS 内联（Critical CSS）：将控制首屏白屏时间的极少部分核心样式直接用 `<style>` 标签写在 HTML 里，其余非核心 CSS 异步延迟加载。
4. JS 标签善用 async 或 defer：防止脚本由于同步等待上方的 CSSOM 而引发级联阻塞，从而让 DOM 树能够顺畅地解析完毕

## 在 CSS 中，使用 rem 作为单位有何缺点

1. 文字大小：保留 rem（但不通过 JS 动态篡改根字号），确保用户更改系统字号时网页能正常无障碍放大。
2. 移动端整页等比：全面拥抱 vw / vh。使用 postcss-px-to-viewport 插件，直接将 px 转化为视口百分比，不再需要通过 `<html>` 的字号倒手转一次，彻底隔离了“字号”与“布局宽度”的逻辑。
3. 响应式范围锁定：利用 CSS 的 clamp()、min()、max() 函数。css
4. 精细组件边距：组件内部改用 em，细线边框、阴影、微调等始终坚持使用 px。

## Flex 布局中的 flex-basis 与 width 有何区别

在 Flex 布局中，flex-basis 和 width 都是用来指定 Flex 项目（子元素）初始大小 的属性，但它们的底层机制和优先级有本质区别。
简而言之：width 是通用物理宽度，而 flex-basis 是 Flex 轴线上的“基准大小”。当两者同时存在时，flex-basis 具有更高的优先级，但它必须服从 min-width（最小宽度）和 max-width（最大宽度）的限制。
