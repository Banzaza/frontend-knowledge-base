# Cursor

## 交互方式

1. Tab（Tab）：自动，类似普通编辑器的代码补全，ESC 否定建议，适合手写代码时使用。
2. Command（Ctrl+K）：手动，选择需要修改的内容，在终端也能用，会根据提示词生成 Shell 命令，适合明确范围且仅修改单文件的任务。
3. Chat（Ctrl+L）：Agent全面接管，自动根据提示词执行任务，适合涉及多文件修改的任务，如架构设计，项目搭建，规范修改等。

- @：可以引用特定文件，文件夹，官方文档，Git 历史，终端输出，截图，实时网页内容，用于强化 Chat 理解我们的任务需求。

## 配置

1. 规则（Rules）：规则是持久的指令，Agent 每次交互前都会读取它，适合配置编码规范，架构设计和约束，使用`/generate`命令可以让 Agent 自动生成一份基于当前代码库的规则。

- cursor.directory：为特定的技术栈提供经过验证的规则，可以直接引入再进行调整。
- 规则类型：项目规则提交到 Git 上维护，个人规则留在本地不要提交。

2. 命令（Commands）：保存为 Markdown 文件，并可以通过“/”触发的可重复使用的指令。

- 在.cursor/commands/中维护指令，通过`slash + <文件名>`触发命令。
- 当我们写了两次以上类似提示词时，就可以把它维护成一个命令。

3. 记忆（Memories）：为 Agent 提供持久的上下文，不用每次对话都从零开始。

## 高级工作流

1. 并行代理（Parallel Agents）：适用于有多个独立任务需要同时进行。
2. 后台代理（Background Agents）：在云端运行，适用于长时间任务，仅限于不敏感的代码。

## 使用技巧

- 先用Plan生成计划文档，审查修改后，再点击Build，让Agent去执行。如何有需求文档或PRD，先用add file添加它们。
- 先表明意图->再提供上下文->再提供约束->进行验证
- 更多的上下文不意味着Agent效果更好，相关性更重要，合理的上下文效果好并且可以节省Token消耗。

## Slack和Linear又是什么

Slack 和 Linear 是当今海外科技公司和现代软件开发团队中最流行的两款协作工具。结合你刚才问的 Background Agents，这两款工具正是目前 AI Agent 最常集成的“指挥中心”和“任务派发平台”。

1. Slack：团队即时通讯工具

- 核心定位： 面向企业与团队的即时通讯与协作平台。你可以把它简单理解为“海外科技圈的飞书（沟通部分）或企业微信”。
- 核心特点： 它以频道（Channel）为核心组织聊天（比如 #前端开发、#产品需求、#服务器报警），支持丰富的消息线程（Thread）讨论。
- 与 AI 的结合： 它是人机交互的绝佳入口。现在很多团队会在 Slack 里直接 @Cursor 或 @Devin（即呼出 Background Agent），像给同事发消息一样吩咐 AI：“帮我修一下登录页面的按钮对齐问题”，AI 就会在后台接单干活。

2. Linear：新一代敏捷项目管理工具

- 核心定位： 专为现代软件开发团队设计的任务追踪与项目管理工具（相当于新一代、更极简的 Jira 或 Trello）。
- 核心特点： 以极致的速度、流畅的快捷键操作和极简的设计美学闻名。产品经理和工程师用它来管理 Bug（缺陷）、Feature（新功能）以及开发周期（Sprint）。
- 与 AI 的结合： 它是标准的“任务清单”。产品经理在 Linear 里新建一个 Bug 工单，只要把工单直接指派（Assign）给 Background Agent，AI 就会自动读取工单描述，去后台写代码、跑测试，最后自动提交代码把工单标记为“已完成”。

三者是如何联动工作的？

在现代 AI 驱动的研发工作流中，这三者的配合非常经典：

1. 发现问题（Slack）： 大家在 Slack 群里讨论发现了一个界面 Bug。
2. 派发任务（Linear）： 团队成员顺手把这条讨论转成 Linear 里的一个待办工单，并把负责人设为 AI。
3. 后台执行（Background Agent）： Background Agent 收到任务后，在云端默默拉取代码、修复 Bug、运行测试。
4. 交付汇报（Slack）： 任务完成后，Agent 自动在 Slack 里 @ 发起人，附上代码修改链接，请人类工程师验收。
