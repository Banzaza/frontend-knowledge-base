# 基本概念

## 一、 模型与算力底层（大脑与基础规则）

这一层决定了 AI 的原生智商、计算成本以及信息处理的物理边界。

- LLM (大语言模型)：基于海量数据训练的文本生成与推理模型。类似整个 AI 系统的核心大脑，负责理解意图与逻辑推理。
- Multimodal (多模态)：能够同时理解与生成文本、图像、音频、视频的模型能力。类似让大脑长出“眼睛和耳朵”，打破纯文字交互的限制。
- Reasoning Models (推理模型)：在回答前会进行内部深度逻辑推演与自我纠错的模型（如 o1/o3、DeepSeek-R1）。类似慢思考大脑，像做数学题打草稿一样，大幅提升复杂逻辑准确率。
- Token (词元)：模型拆分、理解和生成文本的最小计量单位。类似模型的计算货币，直接决定 API 计费成本和单次处理上限。
- Context Window (上下文窗口)：模型单次对话能同时处理和记住的最大 Token 容量。类似大脑的工作台面积，面积越大，单次能塞进去的资料就越多。
- Fine-tuning (微调)：用特定领域的私有数据对通用大模型进行二次训练。类似考前闭关背书，让模型彻底内化特定领域的专业知识或说话风格。
- Quantization (量化)：通过降低模型参数的计算精度来压缩模型体积的技术。类似给模型瘦身，让原本需要昂贵显卡的大模型能在普通电脑或手机运行。

## 二、 交互与知识外挂（突破大脑的记忆局限）

由于大模型知识会过时且缺乏私有数据，需要通过以下技术为其提供准确的上下文和外部知识。

- Prompt Engineering (提示词工程)：设计结构化指令、角色设定与示例，引导模型输出预期结果的技术。类似说话的艺术，教人类如何精准地向 AI 下达指令。
- Context Engineering (上下文工程)：动态组织、裁剪、拼接历史对话、检索资料与环境信息的系统工程。类似考前小抄整理术，在有限的上下文窗口内塞入最精准的背景信息。
- Embedding (向量化)：将文字、图片转化为包含语义特征的数学向量的技术。类似语义翻译器，让计算机能通过计算数字距离，判断两句话意思是否相近。
- Vector Database (向量数据库)：专门用于存储和极速检索海量向量的数据库（如 Milvus、Pinecone）。类似AI 的语义索引图书馆，能在毫秒级时间内找到最相关的资料片段。
- RAG (检索增强生成)：提问时先去外部知识库检索资料，再交给模型总结回答的技术。类似开卷考试，有效解决模型“胡说八道（幻觉）”和缺乏私有数据的问题。
- GraphRAG (图谱增强检索)：先将文档提取为网状“知识图谱”，再结合图谱进行全局检索的技术。类似带思维导图的开卷考，大幅增强跨文档推理和全局总结能力。

## 三、 智能体与工具生态（赋予 AI 行动的手脚）

这一层让 AI 从“只会聊天的对话框”进化为“能自主干活的数字员工”。

- Agent (智能体)：以 LLM 为大脑，具备自主规划、记忆和调用工具能力的自治系统。类似独立工作的打工人，给定目标后能自己拆解步骤并逐步执行。
- Memory (记忆机制)：分为对话内的“短期记忆”和存入外部数据库的跨会话“长期记忆”。类似工作笔记本，让 Agent 记住你的偏好和历史经验，摆脱金鱼记忆。
- Multi-Agent (多智能体协同)：让多个扮演不同角色的 Agent 组成团队，通过分工沟通完成复杂任务。类似项目团队协作（如产品经理 + 程序员 + 测试员协同开发软件）。
- Tool Schema (工具描述规范)：用结构化格式（通常是 JSON）编写的外部工具功能与参数说明书。类似接口说明书，让大模型看懂外部工具叫什么、有什么用、怎么传参数。
- Function Calling (函数调用)：模型根据 Schema 输出标准指令，触发外部程序执行动作的原生能力。类似按按钮的手指，标志着大模型从“输出自然语言”跨越到“控制软件”。
- Skills (技能)：针对特定业务场景，将多个工具与本地操作指令打包成的完整能力闭环。类似封装好的复合大招（例如把“查数据+画图表+发邮件”打包成“周报技能”）。
- MCP (模型上下文协议)：统一大模型应用与外部数据源、工具连接的开放标准协议。类似AI 界的 Type-C 接口，实现不同 AI 客户端与各类工具服务的一键通插。

## 四、 工程编排与质量保障（确保系统安全、可控、好用）

当 AI 应用走向真实业务落地时，必须依赖以下工程化框架进行编排、管控与质检。

- N8N：开源的可视化、节点式工作流自动化编排平台。类似自动化流水线，通过拖拽连线将大模型、RAG 和日常办公软件串联起来。
- Harness (驾驭工程)：为自主运行的 Agent 搭建的受控沙盒、权限隔离与运维管控外壳。类似工业安全带与防护网，防止 Agent 陷入死循环、误删文件或刷爆账单。
- Guardrails (安全护栏)：过滤用户输入（防恶意注入）与模型输出（防违规/泄密）的双向风控机制。类似安检门，确保 AI 的输入和输出始终符合安全与合规红线。
- HITL (人在回路)：在 Agent 执行高风险操作（如转账、发邮件）前，强制暂停等待人类审批。类似人工确认开关，在自动化效率与人类最终控制权之间取得平衡。
- Observability (可观测性)：完整记录 Agent 每一步思考、检索、调用耗时与 Token 消耗的监控工具。类似系统 X 光机，当复杂工作流出错时，帮助开发者快速定位瓶颈和 Bug。
- Evals (基准评测)：通过标准测试集与自动化评分机制，量化评估模型和 Agent 表现的框架。类似期末考卷与质检员，用客观数据衡量提示词或架构改动到底有没有变好。

## 终极串联：一分钟看懂全栈运转流程

当你在电脑上向一个现代 AI 助手下达复杂指令时，这 26 个概念是这样协同工作的：

1. 底层驱动：系统运行在经过 Quantization（量化） 优化的 Multimodal（多模态） 或 Reasoning（推理） LLM 之上，所有信息按 Token 计费并在 Context Window 内流转（特殊场景会提前对模型做 Fine-tuning）。
2. 信息组装：Agent 启动，利用 Context Engineering 和 Prompt Engineering 组装指令，调取你的长期 Memory，并通过 Embedding 技术在 Vector Database 中执行 RAG / GraphRAG 检索。
3. 工具执行：大脑读懂 Tool Schema，通过 MCP 协议发起 Function Calling，调用封装好的 Skills，甚至唤醒其他 Multi-Agent 协同作战。
4. 安全与质检：整套流程在 N8N 流水线上自动流转，外层有 Harness 沙盒和 Guardrails 护航，关键动作触发 HITL 人工审批；后台则由 Observability 实时追踪日志，并靠 Evals 持续迭代优化。
